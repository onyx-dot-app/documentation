Connect your AI tool to Onyx to search the documents you can access in your workspace.
OAuth opens Onyx in your browser so you can sign in and approve access.
You do not need to create an OAuth client or copy a client secret.

## Before you start

- Sign in to Onyx and confirm you can search for a document in the web interface.
- Ask your administrator for your workspace's MCP URL. The examples use `https://onyx.example.com/mcp/`. Replace the domain with your Onyx domain and keep the `/mcp/` path.
- Use a current version of your AI client with Streamable HTTP and OAuth support.
- Confirm that your client can reach the MCP URL. A terminal client connects from its execution environment.
  A hosted connector may connect from the provider's cloud.

The browser approval grants `read:search` access on your behalf.
Review [sign-in and approval](/overview/onyx_anywhere/mcp_server#sign-in-and-approve-access)
for the Onyx screens and permissions. Your Onyx document access still applies.

## Codex

### Add Onyx and sign in

Run these commands in your terminal, replacing the example domain:

```bash
codex mcp add onyx --url https://onyx.example.com/mcp/
codex mcp login onyx
```

Complete the Onyx sign-in and approval in your browser. Then check the configuration and start Codex:

```bash
codex mcp list
codex
```

Inside Codex, enter `/mcp` and check that Onyx is connected. Send the [test prompt](#test-the-connection)
to confirm a search succeeds.

### Configure with TOML

As an alternative to `codex mcp add`, add the following to `~/.codex/config.toml`:

```toml
[mcp_servers.onyx]
url = "https://onyx.example.com/mcp/"
```

Run `codex mcp login onyx` after saving. Keep one `mcp_servers.onyx` table in the file. If Onyx already exists,
update its URL instead of adding another table.

The desktop app, CLI, and IDE extension share configuration on the same Codex host.
See [OpenAI's MCP guide](https://learn.chatgpt.com/docs/extend/mcp) for configuration options.

## Claude Code

### Add Onyx for your user account

```bash
claude mcp add --scope user --transport http onyx https://onyx.example.com/mcp/
claude
```

In Claude Code, enter `/mcp`, select Onyx, and choose **Authenticate**. Complete the browser approval.
Check `/mcp` again and send the [test prompt](#test-the-connection).

Current releases also support authentication directly from the terminal:

```bash
claude mcp login onyx
```

Use `claude mcp list` to inspect configured servers.
See [Claude Code's MCP documentation](https://code.claude.com/docs/en/mcp) for authentication and configuration scopes.

### Share the configuration with a project

For a team repository, put the endpoint in `.mcp.json` at the project root:

```json
{
  "mcpServers": {
    "onyx": {
      "type": "http",
      "url": "https://onyx.example.com/mcp/"
    }
  }
}
```

Each team member approves the project configuration and signs in with their own Onyx account.
Commit the endpoint configuration only. OAuth credentials do not belong in the repository.
Choose either user or project configuration for Onyx to avoid competing definitions.

## Claude Desktop

Use a remote custom connector:

1. Open **Customize > Connectors**.
2. Select **+ Add > Add custom connector**.
3. Name it **Onyx** and enter `https://onyx.example.com/mcp/` with your domain.
4. Continue through authentication settings.
   Choose sign-in and either Claude's published OAuth identity or automatic registration. Onyx supports both.
5. Add the connector and complete Onyx sign-in when prompted.
6. Enable Onyx through the conversation's **+ > Connectors** menu and send the [test prompt](#test-the-connection).

For a managed organization, an owner adds Onyx under **Organization settings > Connectors**.
Members then select **Connect** for Onyx in their own connector list and approve access with their own account.

<Note>
  Claude Desktop remote connectors connect from Anthropic's cloud.
  Your server must be reachable from that infrastructure, even if your laptop can reach it through a VPN.
  The desktop JSON configuration for local processes is a separate setup mechanism.
</Note>

See [Anthropic's custom connector
guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
for current availability and network requirements.

## ChatGPT desktop

1. Open **Settings > MCP servers** and select **Add server**.
2. Name it **Onyx** and choose **Streamable HTTP**.
3. Enter `https://onyx.example.com/mcp/` with your domain.
4. Save, then select **Restart**.
5. Select **Authenticate** for Onyx and complete the browser sign-in and approval.
6. Enter `/mcp` in the composer to inspect connected servers, then send the [test prompt](#test-the-connection).

If you already configured Onyx with Codex on the same host, check the server list before adding it again.
These clients share `~/.codex/config.toml`. See [OpenAI's MCP guide](https://learn.chatgpt.com/docs/extend/mcp)
for the current desktop controls.

### ChatGPT on the web

ChatGPT web uses hosted MCP tools through plugins. It does not read your local Codex configuration.
Adding Onyx in the desktop app therefore does not configure it on the web.
Consult [OpenAI's MCP guide](https://learn.chatgpt.com/docs/extend/mcp)
for the web connection model and your workspace's plugin availability.

## Test the connection

Copy this prompt into your client after connecting:

```text
Use the Onyx MCP server to search for our onboarding guide. Return document titles and source links. Tell me if nothing relevant is found.
```

Replace “onboarding guide” with a document or topic you know exists in your workspace.
Check that the client actually calls an Onyx search tool and receives a response.
A server appearing in a configuration list confirms only that it was added.

If the search returns no matches, try the same query in Onyx.
Confirm the source is indexed and your account can access it. For more examples,
see [MCP workflows](/overview/onyx_anywhere/mcp_server).

## Use a personal access token instead

OAuth is the usual setup for interactive clients. If your environment requires a bearer token,
create a [personal access token](/developers/overview#personal-access-tokens) with `read:search` access.

Keep the token in a local environment variable. For Bash,
this reads it without echoing it or putting the value in the command history:

```bash
read -r -s -p "Onyx personal access token: " ONYX_TOKEN
printf '\n'
export ONYX_TOKEN
```

Run the client from that shell. The variable lasts for the shell session. For a persistent setup,
use your organization's approved local secret management method.

### Codex token configuration

Use this table instead of the OAuth-only table:

```toml
[mcp_servers.onyx]
url = "https://onyx.example.com/mcp/"
bearer_token_env_var = "ONYX_TOKEN"
```

Start `codex` from the shell where `ONYX_TOKEN` is exported.
A desktop app launched separately may not inherit that shell's environment.

### Claude Code token configuration

Use this `.mcp.json` entry instead of the OAuth-only entry:

```json
{
  "mcpServers": {
    "onyx": {
      "type": "http",
      "url": "https://onyx.example.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${ONYX_TOKEN}"
      }
    }
  }
}
```

Start `claude` from the shell where the variable is exported.
Claude Code expands the environment variable when it loads the configuration.
Remove the Authorization header to switch back to OAuth.

## Disconnect or change accounts

To clear Codex's saved OAuth credentials:

```bash
codex mcp logout onyx
```

To remove its server configuration:

```bash
codex mcp remove onyx
```

For Claude Code:

```bash
claude mcp logout onyx
claude mcp remove onyx --scope user
```

If you used a project configuration, remove the Onyx entry from `.mcp.json` instead.
Desktop connector settings also provide disconnect or removal controls.

Removing a client configuration and revoking an Onyx authorization are separate operations.
Use [Onyx's connected app controls](/overview/onyx_anywhere/mcp_server#manage-connected-apps) to revoke the grant.
Revoke a personal access token in Onyx if you used token authentication. To change accounts,
clear the client's saved authentication and reconnect with the intended Onyx account.

## Troubleshooting setup

| Symptom | Next step |
| --- | --- |
| Browser approval never opens | Start authentication explicitly with `codex mcp login onyx`, Claude Code's `/mcp`, or the desktop Authenticate control. |
| Browser finishes but the client stays disconnected | Return to the waiting client and finish any callback prompt. Restart it and inspect its MCP status. |
| Connection fails before sign-in | Confirm the domain, HTTPS certificate, and `/mcp/` path. Check reachability from the client's execution environment or cloud provider. |
| Authentication fails with a bearer token configured | Check the token's expiry and permissions, or remove the bearer configuration and use OAuth. |
| Onyx is connected but never called | Explicitly ask the client to use Onyx and approve the tool call if prompted. |
| The same server appears more than once | Keep a single Onyx definition at the intended configuration scope. |

For Onyx deployment settings and server errors, see the [MCP deployment guide](/deployment/configuration/mcp_server).
