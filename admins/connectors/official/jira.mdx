## How it works

The Jira connector pulls in all tickets from the specified projects every **10** minutes.

For every Jira issue, this connector pulls:

- Title
- Description
- [Common fields](#indexed-metadata)
- Comments

The connector can index only the content that its Jira account can access.
An API token does not give its owner additional Jira permissions.

## Setting up

### Authorization

#### 1. Choose a connector account

Use a dedicated Jira account for the connector.
This makes its access easier to review and prevents a personal account change from stopping the connector.

Create the account or choose an existing account before you create the API token.
Then grant the account the permissions for your connector type.

##### Indexing without permission sync

For indexing without permission sync, the Jira account needs:

- Jira product access.
- **Browse Projects** for every project that you want to index.
- Access to each issue security level used by the indexed issues.
- Access to each restricted comment that you want to index.

Jira omits projects, issues, and comments that the account cannot access.
A standard Jira user can run the connector if the user has all required access.

##### Additional permissions for permission sync

<Warning>
  Onyx treats everything inside a Jira project as accessible to everyone who can see the project.
  It does not sync Jira issue security levels or restricted comment visibility.
  Do not enable permission sync for projects that use these restrictions.
</Warning>

For permission sync, grant the account all indexing permissions plus:

- **Jira Cloud:** **Administer Jira** globally, or administrative access to every indexed project.
  For company-managed projects, grant **Administer Projects**. For team-managed projects,
  assign the **Administrator** role. Also grant **Browse users and groups** globally,
  unless the account has **Administer Jira**.
- **Jira Data Center 9 through 11:** add the account to a group with the **Jira administrators** or
  **Jira System administrators** global permission. Data Center requires this access to read group membership.

Onyx uses these permissions to read each project's permission scheme, resolve project roles, and read group membership.
The account also needs **Browse Projects** for all indexed projects.

<Note>
  **Administer Jira** does not always grant access to issue content.
  Confirm **Browse Projects** and issue security access separately.
</Note>

#### 2. Check and grant the account's permissions

Ask a Jira administrator to complete these checks while signed in to Jira:

<Steps>
  <Step title="Check global permissions in Jira Cloud">
    Go to **Settings > System > Global permissions**. Confirm that the account has the Cloud permissions listed above,
    either directly or through a group. If a permission is missing,
    use **Grant permission** or add the account to a group that has it.
    See Atlassian's [Cloud global permission
    instructions](https://support.atlassian.com/jira-cloud-administration/docs/view-grant-revoke-global-permissions-in-jira/).
  </Step>

  <Step title="Check global permissions in Jira Data Center">
    Go to **Administration > System > Global permissions**.
    Confirm that the account belongs to a group with **Jira administrators** or **Jira System administrators**.
    Data Center grants global permissions to groups, not individual accounts.
    See Atlassian's [Data Center global permission
    instructions](https://confluence.atlassian.com/adminjiraserver/managing-global-permissions-938847142.html).
  </Step>

  <Step title="Check Cloud company-managed project access">
    Go to **Settings > System > Admin Helper > Permission Helper**. Enter the connector account, a representative issue,
    and the permission to check.

    Check **Browse Projects** and **Administer Projects**.
    Repeat the check with a representative issue from each permission scheme and issue security level in use.
    If a project permission is missing, grant it to the account, one of its groups,
    or one of its project roles in the project's permission scheme.
    The Permission Helper applies to company-managed projects.
    See Atlassian's [Cloud Permission Helper
    instructions](https://support.atlassian.com/jira-cloud-administration/docs/check-a-users-access-from-a-work-item/).
  </Step>

  <Step title="Check Cloud team-managed project access">
    In the project's sidebar, go to **Space settings > Access**.
    Confirm that the connector account has the **Administrator** role.
    Review the project's access level and each role that can view issues.
    See Atlassian's [team-managed access
    instructions](https://support.atlassian.com/jira-software-cloud/docs/manage-how-people-access-your-team-managed-project/).
  </Step>

  <Step title="Check Data Center project and issue access">
    Go to **Administration > System**, then select **Permission helper** in the left panel. Enter the connector account,
    a representative issue, and **Browse Projects**.
    Repeat the check with a representative issue from each permission scheme and issue security level in use.
    See Atlassian's [Data Center Permission Helper
    instructions](https://confluence.atlassian.com/adminjiraserver/jira-admin-helper-938847791.html).
  </Step>

  <Step title="Test representative restricted content">
    Sign in as the connector account.
    Confirm that it can open representative issues and comments from each restriction type that you intend to index.
  </Step>
</Steps>

#### 3. Create the token

<Steps>
  <Step title="Jira Cloud token">
    Create an API token from the connector account.
    Follow Atlassian's [API token
    instructions](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/).

    If you create a token with scopes, enable **Using scoped token** when you configure the connector in Onyx.

    For indexing, grant the token the `read:jira-work` scope. Permission sync also reads permission schemes,
    project roles, users, groups, and group membership.
    Grant `read:jira-user` and `manage:jira-configuration` in addition to `read:jira-work`,
    or grant the complete granular read scopes listed for these Jira APIs:

    - [Issue search and fetch](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/)
    - [Project permission schemes](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-project-permission-schemes/)
    - [Project roles](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-project-roles/)
    - [Groups and group members](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-groups/)

    Token scopes limit the token. They do not replace the connector account permissions described above.
  </Step>

  <Step title="Jira Data Center token">
    Create a personal access token from the connector account.
    Follow Atlassian's [Jira Data Center token
    instructions](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html).

    The token has the same access as its Jira account.
    Jira Data Center personal access tokens do not use Jira Cloud API scopes.
  </Step>
</Steps>

### Permission sync limitations

Review these limitations before you enable permission sync:

- Onyx maps Jira users to Onyx users by email address. Jira Cloud profile visibility can hide `emailAddress`, even
  from an administrator's API token. Jira Data Center can also hide or mask user email addresses. A missing, hidden,
  or masked email prevents Onyx from mapping that user.
  Review Atlassian's [profile visibility
  documentation](https://developer.atlassian.com/cloud/jira/platform/profile-visibility/)
  and [Data Center email visibility
  settings](https://confluence.atlassian.com/adminjiraserver0912/configuring-jira-application-options-1346048127.html).
- Onyx supports static **Browse Projects** grants to users, groups, and project roles. Dynamic grants such as
  Reporter, Assignee, Project Lead, and custom user fields cannot map to a static Onyx access list.
- Onyx treats Jira's **Anyone** and **Application access** grants as accessible to all Onyx users.
  Jira application access normally includes only licensed Jira users.
  This mapping can give access to Onyx users who cannot access Jira.
- Permission sync requests up to 9,999 Jira groups visible to the connector account.
  Jira can apply a lower limit, so large sites might not sync every group.
- Jira Cloud API tokens expire after 1 to 365 days. Rotate the token before it expires.

### Indexing

<Steps>
  <Step title="Open Jira connector">
    Go to the Admin Panel and select the **Jira** connector.
  </Step>

  <Step title="Provide credentials">
    For Jira Cloud, enter the connector account's email address and API token:

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraCloudAuth.png" alt="Onyx Jira Cloud connector authentication form"/>

    For Jira Data Center, enter the personal access token:

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraServerAuth.png" alt="Onyx Jira Server personal access token form"/>
  </Step>

  <Step title="Choose projects and filters">
    For each project you want to index, provide a single URL to any page in the project.
    Optionally specify users whose comments should not be indexed (useful to ignore certain bots). For example:

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraIndex.png" alt="Jira indexing configuration showing project URLs and excluded commenters"/>
  </Step>

  <Step title="Start indexing">
    Select **Connect**. Onyx pulls the Jira issues that the connector account can access every **10** minutes.
  </Step>
</Steps>

### Indexed metadata

```
- Project ID
- Issue Type
- Issue Key
- Summary
- Description
- Priority
- Labels
- Assignee
- Reporter
- Comments
- Status
- Resolution
- Created
- Updated
```
